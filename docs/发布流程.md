# 发布流程

1. 改 [package.json](../package.json) 的 `version`（两端与安装包版本在构建期取用这一处）
2. `pnpm changelog` 生成 CHANGELOG
3. `git add package.json CHANGELOG.md` → `git commit -m "chore: 发布 vx.y.z"` → `git push`
4. `git tag vx.y.z` → `git push origin vx.y.z`，触发 [deploy.yml](../.github/workflows/deploy.yml)：build → 部署 Pages；desktop（Windows runner，`pnpm desktop:dist`）产出安装包；release 等这两个都完成后发布 Release（正文取 CHANGELOG 中 `## vx.y.z` 小节）
5. 打开验证

| 用途 | 地址 |
| --- | --- |
| 仓库 | https://github.com/zhang-brook/schema-editor |
| Pages | https://zhang-brook.github.io/schema-editor/ |
| 更新日志 | https://github.com/zhang-brook/schema-editor/blob/main/CHANGELOG.md |
| Release | https://github.com/zhang-brook/schema-editor/releases |

Release 资产：`schema-editor-vx.y.z.zip` / `.tar.gz`（网页版）、`schema-editor-vx.y.z-setup.exe`（安装版）、`schema-editor-vx.y.z-portable.exe`（免安装版）、`latest.yml`（应用内检查更新的元数据）与 `schema-editor-vx.y.z-setup.exe.blockmap`（增量下载）。文件名里的版本号取自根 `package.json`，与 tag 保持一致。

## 注意

- CHANGELOG 小节标题必须与 tag 一致，否则 Release 正文只有兜底文案
- 同版本号重复执行 `pnpm changelog` 会被守卫拦截（exit 1），需先删掉该小节或还原 CHANGELOG.md
- 只有推送 `v*` tag 才触发部署，普通提交不会
- Pages 部署不等 Windows 打包；Release 要等安装包产出，两者一起挂载
- 打包固定 `--publish never`：安装包与 `latest.yml` 由 release job 统一挂载。electron-builder 在 tag 上构建会默认自行上传，CI 没有 `GH_TOKEN` 时整条打包会失败
- 未配置代码签名，首次安装仍会出现 SmartScreen 提示
- 已发布的 Release 不要删掉 `latest.yml` 或改动画廊里的安装包，否则已安装的应用检查不到更新或校验失败
- 应用内更新只读 `releases/latest`，GitHub 会跳过草稿与预发布版本；标记为 prerelease 的 tag 打包再全，安装版也检查不到
